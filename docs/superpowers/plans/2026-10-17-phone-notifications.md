# 휴대폰 알림과 캐릭터 상태 연결

사용자 요청: 업무 패널 간격을 좁히고 일일업무 아래에 알림 카드를 표시한다.
카드에는 확인/미확인 배지, 내용 팝업, 답장 요청을 제공한다.
미확인 알림이 있으면 이전 typing 이미지를 alert 상태로 쓰고 분홍색 점멸과
확인 완료 버튼을 표시한다. typing 이미지는 사용자가 제공한 GIF로 교체한다.

## 구현 경계

1. `office_notifications.py`: SQLite 알림 저장·중복 방지·확인 상태·수신기 상태.
2. `notification_capture.py`: 현재 Windows 세션에 표시되는 Phone Link/메신저
   알림 배너만 접근성 정보로 읽는 별도 로컬 프로세스. 마우스·키보드·AI 호출 없음.
   표시되지 않은 알림·숨겨진 내용·과거 전체 문자 수집은 지원 범위가 아니다.
3. `app.py`: 기존 로컬 Host/Origin/토큰 검증을 재사용한 목록·확인 API와 수신기 시작.
4. `work-notifications.js/css`: 내부 스크롤 카드·팝업·명시적 확인 완료·답장 작업 요청.
   답장은 기존 에이메스 도구로 원래 앱의 실제 수신자를 확인해 수행한다.
   지원되지 않는 앱에 직접 전송 성공을 표시하지 않는다.
5. `workdesk.js/html`, `workstage.css`: 알림 우선 캐릭터 상태·채팅 브리지·좁은 간격.
6. `companion_assets.py`: 기존 typing 등록을 alert로 보존한 후 제공 GIF를 typing에 적용.

## 확인 범위

사용자 지시에 따라 별도 자동 테스트는 추가·실행하지 않는다.
구문 검사, 실제 수신 프로세스 초기화·상태, 사용자 화면의 레이아웃을 구별한다.
새 휴대폰 알림과 앱별 실제 답장은 사용자 수신·전송 요청으로 확인한다.
개인 DB·설정·첨부 GIF 원본·동시에 저장된 에이메스 변경을 보존한다.
