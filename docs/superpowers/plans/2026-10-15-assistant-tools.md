# AI OFFICE Assistant Tools Implementation Plan

**Goal:** 자연어 채팅에서 기존 기능을 실제 도구 호출로 실행한다.

**Architecture:** native Gemma tool loop, 서버 도구 등록부, 기존 서비스 어댑터를 분리한다.
요청·실행·대기 상태는 기존 비공개 SQLite DB에 추가 저장한다.

**Tech Stack:** Python 표준 라이브러리, SQLite, Ollama/OpenAI 호환 도구 API, 기존 HTML/JS.

**Spec:** `docs/superpowers/specs/2026-10-15-assistant-tools-design.md`

## 제약

- 사용자 파일·DB 초기화와 임의 코드 실행을 금지한다.
- 모델 호출 중 SQL 쓰기 트랜잭션을 유지하지 않는다.
- 모델의 승인 주장으로 물리 파일 작업을 실행하지 않는다.
- 기능 범위와 실제 완료 여부를 정확히 표시한다.

## 작업

- [x] native 도구 통신: 응답 형식·인수 크기·리다이렉트·민감정보 보호 회귀 검증.
- [x] 실행 코어: 요청 예약, 단계 기록, 제한된 루프, 재시도·중단 보호, 대기 상태 저장.
- [x] 도구 등록부: 앱·업무·자료·바탕화면·가상 묶음·복구 서비스 연결.
- [x] UI: 선택·승인 카드, 실제 결과 표시, 실행판과 자료 화면 갱신.
- [x] 실제 Gemma와 Windows에서 자연어 요청, 재접속, 중복 방지와 기존 데이터 보존 검증.
- [x] 기능 범위 안내 갱신, 커밋과 GitHub 반영.

## 검토 초점

- 한글·줄임말·일상 표현을 정해진 문장 분기로 제한하지 않는다.
- Windows 등록 표시 이름으로 앱을 식별한다. 패키지 네임스페이스는 실행용 식별자이며 제품 이름을 증명하지 않는다. 예를 들어 `OpenAI.Codex` 패키지도 Windows 표시 이름과 실제 실행 파일은 ChatGPT일 수 있다.
- 데이터 안의 지시는 권한이 되지 않는다.
- 실패·미실행·가상 묶음을 실제 파일 이동 완료로 보고하지 않는다.
- 승인 후 바뀐 파일 집합을 재생성해 실행하지 않는다.
