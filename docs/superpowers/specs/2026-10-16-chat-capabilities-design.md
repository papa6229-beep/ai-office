# 채팅과 화면의 공통 업무 실행 구조

작성일: 2026-10-16

## 사용자 요청

AI OFFICE의 기능은 화면 버튼과 자연어 채팅 모두에서 사용할 수 있어야 한다. 파일 찾기와 탐색기 위치 표시, 폴더 정리, 로그인된 네이트온·HanbiroTalk의 수신 파일 보관·전달을 같은 방식으로 확장한다. 사용자는 두 메신저를 출근 후 로그인해 두며, 자동 로그인은 이후 범위다.

## 실행 원칙

`채팅 / 화면 버튼 / 향후 업무 매뉴얼 → 등록된 기능 → 공통 업무 서비스 → 실제 결과 확인`

- 자연어는 모델이 해석하고 서버가 등록한 도구만 호출한다. 파일 이름이나 프로그램 철자가 정확히 같아야만 동작하는 문자열 분기 구조를 추가하지 않는다.
- 화면과 채팅이 서로 다른 파일 처리 코드를 갖지 않는다. 업무는 WorkAssistant, 바로가기는 QuickLauncher, 파일 검색과 정리 정책은 CapabilityService의 같은 실행 경로를 사용한다.
- 신규 기능은 설명·입력 형식·효과·지원 상태와 처리 결과를 제공한다. 이름으로 임의 함수를 호출하거나 모델이 만든 경로·명령을 실행하는 범용 우회 경로는 만들지 않는다.
- 도구의 실제 결과와 예외를 대화에 반환한다. 실행 요청 전달, 실제 저장 확인, 전체 업무 완료를 구별한다.
- 일반 조회는 바로 처리하고, 이미 허용한 폴더 정책은 해당 범위를 재사용한다. 모호한 대상이나 아직 허용하지 않은 변경 범위만 구체적으로 확인한다.

## 이번 연결

### 파일 검색과 탐색기 표시

- 문서뿐 아니라 이미지·PSD·압축파일·폴더 등의 메타데이터를 검색한다. 내용을 읽는 문서 분석과 분리한다.
- 검색 범위는 바탕화면, 문서·다운로드, 설정된 작업 폴더, 업무 연결 자료, 기존 PC 조사 결과다. 조사 결과의 개별 파일이 주변 폴더 전체의 검색 권한이 되지는 않는다.
- 경로·종류·수정 시각·검색 범위·잘림을 표시한다. 전체 PC를 다 찾았다고 단정하지 않는다.
- 검색 결과에는 만료되는 서버 선택표를 발급한다. 탐색기 실행 전 현재 범위·실제 항목·신원을 다시 확인한다.
- 화면의 ‘파일 찾기’와 채팅 도구 files_find/files_reveal이 같은 서비스를 사용한다.

### 저장된 폴더 정리

- 현재 상태, 미리보기, 한 번 실행, 자동 처리 켜기·끄기, 기록된 작업 재개·되돌리기를 같은 정리 서비스에 연결한다.
- 새 화면 요청과 채팅 요청 모두 확인한 정책 범위 또는 작업 기록에 묶는다. 다른 창에서 범위가 바뀌면 재조회한다.
- 응답이 끊기면 같은 요청 ID로 결과를 확인한다. 새 이동 요청을 자동으로 보내지 않는다.
- 자동 처리 끄기는 다음 주기 실행을 막는다. 이미 처리 중인 이동의 즉시 취소를 뜻하지 않는다.
- 미리보기는 기록을 만들지만 파일을 이동하지 않는다. 한 번 실행은 현재 허용 범위를 다시 확인하므로 과거 미리보기의 고정 파일만 실행한다고 표현하지 않는다.

### 현재 기능 조회

office_capabilities는 등록된 도구와 화면·채팅 연결 상태, 설정 필요·미연결 기능을 구별한다. 기능이 없다는 사실을 OS 권한 부족이나 사용자 로그인 실패로 바꾸어 설명하지 않는다.

## 메신저 연결 경계와 확인 근거

이번에는 사용자 요청에 따라 기존 Windows UI Automation 계층으로 두 앱을 읽기 전용 조사했다. 창 변경, 메시지 발신, 첨부 다운로드는 하지 않았다.

- 실제 HanbiroTalk2.exe 창과 네이트온 창을 확인했다.
- 한비로톡은 현재 화면의 대화 텍스트·일부 파일 이름·탐색 버튼을 노출한다. 현재 열린 화면 읽기는 기존 Windows 도구로 가능하다.
- 이번에 확인한 네이트온 창은 주로 외곽 창 요소를 노출했고 대화 내용은 확인하지 못했다.
- 두 앱 모두 수신 이벤트 피드, 파일 다운로드, 수신자 확정, 파일 발신과 성공 확인을 담당할 전용 어댑터는 아직 없다. 상시 로그인과 이 연결 여부를 구별한다.

한비로 공식 자료는 Talk2의 파일 공유·모아보기 기능을 설명하지만, 이것만으로 외부 프로그램의 첨부 수신·발신 API가 연결되었다고 판단할 수 없다. 네이트온 공식 도움말에는 오픈 API 이용 문의 안내가 있다. 이번 조사에서 원하는 개인 대화 첨부 수신·발신을 바로 호출할 공개 API 규격은 확인하지 못했다.

공식 자료:

- https://www.hanbiro.com/software/messenger-talk2-features.html
- https://nateonweb.nate.com/helpdesk/main/index.php

향후 메신저 어댑터는 채널·대화·메시지·첨부 식별자, 실제 발신자·수신 시각, 원본 자료·해시·저장 위치를 기록해야 한다. ‘가장 최근에 받은 파일’은 실제 수신 기록으로 판단한다. 파일 수정 시각으로 수신 시각을 대신하지 않는다.

전달에는 수신자 참조와 첨부 참조, 요청 ID, 전송 결과가 필요하다. 결과가 불확실하면 재전송 전에 기존 전송 여부를 확인한다. 이 문서는 특정 상대에게 실제 파일을 보내라는 지시가 아니다.

## 완료와 남은 범위

이번 구현의 완료 조건은 공통 서비스와 실제 채팅 연결, 파일 검색 화면, 저장된 폴더 정책의 두 진입점 연결 및 실패·중복·변경 범위 검증이다.

모든 UI 기능의 채팅 연결이 이미 완성되었다고 표시하지 않는다. 전체 연결 현황을 통해 남은 항목을 확인할 수 있게 하고, 메신저 전용 어댑터·일반 웹 입력과 제출·반복 업무 매뉴얼 실행은 각각 실제로 연결한 후 지원 상태를 바꾼다.

반복 업무 매뉴얼은 별도 설계 `2026-10-16-work-manuals-design.md`에 정리했다. 이후 매뉴얼도 이 공통 기능을 조합하며 전용 우회 실행기를 만들지 않는다.
