# Aemeath 업무 매뉴얼 — 설계 초안

작성일: 2026-10-16

## 목적

사용자가 반복해서 수행하는 업무의 판단 기준과 처리 순서를 축적한다. 사용자가 채팅으로 업무를 맡기면 Aemeath가 관련 매뉴얼을 찾아 실제 자료와 현재 화면을 확인하고, 연결된 도구로 처리하며 결과를 기록한다.

첫 적용 사례는 웹 일일 업무보고서다. 이번 설계는 정기 실행이나 실제 보고서 제출을 요청한 것으로 취급하지 않는다. 웹사이트의 실제 입력 구조와 사용자의 작성 예시는 추가로 확인해야 한다.

## 현재 확인한 기반과 부족한 부분

- `assistant_tools.py`의 ToolRegistry와 `assistant_runtime.py`의 AssistantRuntime이 채팅의 실행 경로다. 매뉴얼도 이 실행 경로를 사용한다.
- `work_assistant.py`의 report 처리는 현재 업무 기록을 바탕으로 로컬 초안을 저장한다. 외부 보고 사이트에 제출하는 기능은 아니다.
- 전용 Chrome에서 사이트 열기, 본문 읽기, 링크 이동, 스크롤, 화면 분석이 연결되어 있다. 웹 입력란 채우기, 선택, 저장·제출은 아직 도구로 연결되어 있지 않다.
- 업무별 매뉴얼 저장, 버전 관리, 관련 매뉴얼 검색은 아직 없다.
- 기존 실행에는 요청 중복 방지와 도구 처리 기록이 있다. 매뉴얼 실행은 이를 재사용하되, 여러 단계에 걸친 재개와 최종 제출 확인을 보완해야 한다.

## 선택한 방향

로컬 매뉴얼 보관함을 기존 채팅 실행기에 연결한다. 별도 자동화 프레임워크나 모델 재학습은 도입하지 않는다.

단순한 보고서 서식만으로는 자료 선택과 실행 순서를 표현하기 어렵다. 반대로 화면 클릭을 그대로 녹화한 절차만으로는 오늘의 상황을 판단하기 어렵다. 따라서 사람이 읽는 지침·예시와 실행에 필요한 구조화된 항목을 함께 보관한다.

Agent Skills 공개 형식의 이름·설명으로 발견하고 필요할 때 본문을 읽는 방식을 참고한다. 형식 자체가 웹 조작 기능을 제공하는 것은 아니다.

참고: https://agentskills.io/home

## 사용자 경험

1. **등록:** “이게 내 일일보고서 작성 방식이야. 매뉴얼로 저장해.”라고 설명과 예시를 전달한다. 기존 매뉴얼과 겹치면 신규 생성 또는 기존 항목 수정을 제시한다.
2. **정리:** Aemeath가 목적, 자료 출처, 판단 기준, 작성 예시, 처리 단계와 완료 조건을 초안으로 묶는다. 사용자는 한 화면에서 수정하고 저장한다.
3. **보관:** ‘업무 매뉴얼’ 메뉴에서 검색·열람·편집·사용 중지를 할 수 있다. 채팅에서도 같은 기능을 호출한다. 실사용 매뉴얼과 자료는 사용자 로컬 데이터로 저장하며 소스 저장소에 넣지 않는다.
4. **실행:** “오늘 일일보고서 작성해줘” → 관련 매뉴얼 선택 → 오늘 자료 확인 → 절차 수행 → 결과 확인 → 실행 기록 저장.
5. **예외:** 매뉴얼이 여러 개면 해당 후보만 제시한다. 필요한 자료가 없으면 빠진 항목만 질문한다. 도구가 연결되지 않았으면 해당 단계가 미지원임을 보여준다. 실제 실행 없이 완료로 표시하지 않는다.
6. **개선:** “앞으로 완료 업무부터 적어”처럼 지속 적용을 명시한 지시는 매뉴얼 새 버전에 반영한다. “오늘만 이 항목은 빼”는 이번 실행에만 적용한다. 모호하면 적용 범위를 확인한다.

진행 과정은 기존 업무 상세 팝업에서 보여주고, 사용자 응답이 필요한 항목은 INBOX에 연결한다. 메인 화면에 보고서 패널을 다시 만들지 않는다.

## 매뉴얼 한 건의 구성

| 항목 | 내용 |
|---|---|
| 이름·설명·호출 예시 | 어떤 요청에 사용할 매뉴얼인지 |
| 대상 | 사이트 주소, 메뉴·역할 등 실제 작업 범위 |
| 자료 출처 | 업무 기록, 지정 문서·폴더, 사이트의 특정 영역 |
| 판단 기준 | 보고 대상, 날짜 기준, 포함·제외 조건, 완료·진행 구분 |
| 작성 형식 | 항목 순서, 문체, 길이, 예시·서식 |
| 처리 단계 | 단계별 목표, 사용할 수 있는 도구, 다음 단계로 넘어가는 조건 |
| 예외 처리 | 자료 없음, 로그인 필요, 사이트 변경, 이미 작성된 보고서 |
| 실행 범위 | 초안 작성, 입력, 저장·제출 중 사용자가 맡긴 범위 |
| 완료 조건 | 저장된 날짜·대상·내용 등 실제로 다시 확인할 결과 |
| 버전 | 변경 내용과 수정 시각 |

절차는 고정 화면 좌표 대신 “팀장 보고서의 오늘 항목을 확인한다” 같은 의미와 확인 조건으로 표현한다. 매뉴얼 본문에 임의 실행 코드를 넣어 실행하는 기능은 포함하지 않는다.

## 저장과 실행의 경계

최소 저장 단위는 다음과 같다. 실제 DB 마이그레이션은 구현 단계에서 작성한다.

- **manuals:** 식별자, 이름, 설명, 활성 상태, 현재 버전.
- **manual_versions:** 변경 불가능한 지침·규칙·단계·자료 참조·예시 스냅샷과 변경 이유.
- **manual_runs:** 매뉴얼 버전, 사용자 요청·대상 날짜·대상 사이트, 연결 업무, 실행 상태, 결과.
- **manual_run_steps:** 단계별 상태와 기존 도구 실행 기록의 참조, 확인 근거, 오류 또는 대기 이유.

실행을 시작하면 매뉴얼 버전을 고정한다. 실행 중 매뉴얼을 편집해도 이미 시작한 작업의 절차가 바뀌지 않는다. 사용자 파일과 매뉴얼에 들어 있는 문자열은 실행 권한을 추가하지 않는다. 실제 동작은 기존 도구와 사용자가 맡긴 실행 범위를 따른다.

실행 상태는 준비·진행·응답 대기·실패·결과 미확인·완료·취소를 구별한다. 저장 요청 후 연결이 끊겼다면 결과 미확인으로 남기고 저장 여부부터 다시 확인한다. 같은 날짜·대상 보고서의 기존 항목을 확인해 중복 작성을 막는다. 동일 날짜라는 이유만으로 명시적인 수정 요청까지 차단하지 않는다.

## 기존 실행기와 연결

채팅은 먼저 활성 매뉴얼의 이름·설명만 검색하고, 관련된 매뉴얼 본문과 필요한 예시만 불러온다. 모든 매뉴얼 전문을 매번 모델에 전달하지 않는다.

매뉴얼 조회·작성·수정 도구를 ToolRegistry에 추가하고, 실행에는 기존 도구를 재사용한다. 매뉴얼의 단계 기록은 실제 도구 결과에 연결한다. 매뉴얼에 단계가 적혀 있다는 이유만으로 성공 처리하지 않는다.

일일 보고서에는 현재 업무 목록뿐 아니라 해당 날짜의 활동·메모·자료 근거도 조회할 수 있어야 한다. 기존 실행기의 호출 횟수 제한과 중단 후 이어가기 역시 실제 보고서 흐름에 맞춰 보완한다. 무제한 반복 실행으로 처리하지 않는다.

## 첫 일일보고서 매뉴얼에 확인할 내용

- 실제 사이트와 팀장 보고서의 위치.
- 평소 작성한 보고서 예시와 항목별 입력 규칙.
- 오늘 내용을 판단할 자료 출처와 누락 시 처리 방식.
- 기존 보고서가 있을 때 갱신할 범위.
- “작성해줘”가 초안·입력·저장 중 어디까지 뜻하는지.

2026-10-16에 다음 사항을 실제 화면에서 확인했다.

- 바로가기 ‘일업무보고서’의 대상은 `https://webdesign-daily-report.vercel.app/studio-admin`이다.
- 관리자 로그인에서 보고서 비밀번호를 입력하고 ‘보고서 관리 열기’를 누르면 작성 화면으로 진입한다. 사용자가 이번 접속에 제공한 비밀번호는 이 문서에 저장하지 않는다.
- 작성 날짜, ‘팀장 업무 기록’, 브랜드 작업 현황, 타부서 요청사항, ‘상세페이지 검수 완료 내용’과 ‘보고서 저장’ 버튼이 있다.
- 팀장 업무 기록은 한 줄에 하나씩 적고 공용 보고서에 표시하는 구조다. 팀원별 영역에는 개인 보고서 자동 집계가 표시된다.
- 검수 완료 내용 역시 한 줄에 한 건씩 붙여넣는 구조다.
- 입력란의 활성 상태와 화면 진입까지 확인했다. 보고서 내용을 바꾸거나 ‘보고서 저장’을 누르지 않았다.

위 접속은 개발 보조 도구로 확인한 결과다. AI OFFICE 제품의 채팅 실행기에 로그인·웹 양식 조작이 연결되었다는 뜻은 아니다. 오늘의 업무와 다른 사이트에서 어떤 내용을 가져와 어느 항목에 배치할지는 사용자의 실제 작성 규칙을 더 확인해야 한다.

## 구현 순서와 완료 기준

1. 매뉴얼 등록·편집·검색·버전 보관과 채팅에서 관련 매뉴얼을 불러오는 흐름.
2. 실제 일일보고서 매뉴얼 한 건으로 오늘 자료에서 정해진 형식의 초안을 만들고 부족한 자료만 질문하는 흐름.
3. 실제 사이트의 입력·저장 기능 연결, 중복 확인과 저장 결과 재확인.

**전체 완료 기준:** 사용자가 첫 매뉴얼을 저장한 뒤 “오늘 일일보고서 작성해줘”라고 하면 해당 버전의 규칙과 실제 업무 근거로 처리하며, 맡긴 범위의 결과를 확인하고 이력을 남긴다. 사이트 저장 기능을 연결하기 전에는 초안 단계까지만 구현되었다고 표시한다.

현재 상태: 설계 초안과 실제 사이트 진입 조사 완료. 제품 기능과 DB는 변경하지 않음. 로그인 외 보고서 내용 입력·저장은 수행하지 않음.
