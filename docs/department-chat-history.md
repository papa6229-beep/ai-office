# 부서 대화의 질문·답변 이력 표시

2026-11-04 요청 bbefb1605b78484b9062bb448c2514bc.

부서 작업창은 원본 Codex 대화를 읽어 표시한다. 대용량 디자인 대화의 조회 한도를 지키기 위해 원본은 한 회씩 조회한다. 이전 구현은 최신 한 회의 답변에 Office의 과거 전달 질문 최대 40개를 합쳤다. 그래서 이전 회차 답변을 읽기 전에 그 질문만 화면에 쌓였다. 실제 원본 답변은 삭제되지 않았다.

`project_panels.py`는 원본 페이지의 회차 범위에 속하는 전달 질문만 그 페이지에 합친다. 위치를 아직 확인하지 못한 최근 전달·미확인 전송의 기존 표시는 유지한다. 전달 영수증 목록은 별도로 보존하며, 원본 질문·답변·첨부·진행 상태를 변경하지 않는다. 응답의 `history_window`는 읽은 회차와 가장 이른 시작 시각을, `history_revision`은 `2026-11-04-paired-history-v1`을 제공한다.

`project-panels.js`는 처음 보이는 창에 현재 회차부터 최대 6회 대화를 순차로 채운다. 최초 조회가 먼저 표시되고 이전 5회를 한 회씩 더 읽으며, 실시간 갱신은 계속 최신 한 회만 읽는다. 더 오래된 기록은 기존 ‘이전 대화 더 보기’로 이어진다. 자동 조회 중에는 같은 창의 중복 조회를 막고, 접기·닫기·조회 실패·커서 변화 없음에서 멈춘다. 읽은 회차의 커서는 최신 갱신으로 되돌리지 않는다. 브라우저에 남은 전달 완료 질문 사본도 원본 이력을 읽은 범위에 맞춰 표시하며 미확인 전송 사본은 유지한다.

수정한 Python 소스로 실제 8개 부서의 원본 이력을 조회했다. 최근 최대 6회에서 각 부서의 과거 답변을 확인했고 조회 범위 밖의 오래된 전달 완료 질문은 0개였다. 개발부서는 수정 전 질문 40개와 최신 회차 답변만 반환했으나, 수정한 소스의 최근 6회 조회에서는 질문 6개와 답변/진행 메시지 16개를 확인했다. 조사 중 실시간 진행 메시지가 늘어 개수는 이후 달라질 수 있다.

Python AST·Node 구문·diff를 확인했다. 테스트는 추가·실행하지 않았다. 이 관찰은 저장한 Python 소스의 실제 원본 조회이며, 서버가 새 모듈을 로드한 확인이나 사용자 앱의 실제 표시·클릭 검수와는 구별한다. 실제 소스 영수증은 현재 요청의 정상 reload broker에 등록하고 화면 적용은 사용자가 직접 진행한다. 근거는 비공개 `local_backups/department-history-20261104/`에 보관한다.
