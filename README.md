# AI OFFICE · 로컬 업무 콘솔

AI OFFICE는 빠른 실행·스트림덱·채팅 지시로 업무를 관리하고 대행하는 Windows 설치형 제품을 목표로 합니다. 업무 등록·관련 자료·메신저 수신과 전송·처리 이력·일일 보고서를 하나의 업무 흐름으로 연결하며, 파일 정리는 이를 돕는 부수 기능입니다. 제품화·개인별 AI 연결·수익화까지의 방향은 [AUTOMATION_DIRECTION.md](AUTOMATION_DIRECTION.md)에 정리했습니다. 이 문단은 제품 목표이며 아래 목록이 현재 구현 범위입니다.

## 주요 기능

- 화면은 차콜 패널·겹테두리·머스터드 선택 표시를 사용하는 레트로 콘솔 스타일입니다. 한글 Pretendard와 영문·숫자 Barlow Condensed 서체를 앱에 포함해 인터넷 없이 표시하며, 배포 출처와 라이선스는 `assets/fonts/`에 보관합니다. 채팅·자료·설정·팝업·사용 안내에 같은 스타일을 적용합니다.
- 기본 운영 화면은 왼쪽 채팅·오늘의 업무, 오른쪽 프로그램·웹사이트·폴더 바로가기 실행판의 2분할입니다. 업무를 누르면 상태·진행 이력·메모·관련 자료 팝업이 열립니다. 기본 화면의 보고서 패널은 제거했습니다.
- 바로가기는 추가·수정·삭제·순서 변경·이모지/이미지 아이콘을 지원합니다. Windows 시작 메뉴의 일반 설치 앱·Store 앱을 이름으로 검색해 등록하거나 실행 파일을 직접 선택합니다. 목록 새로고침은 Windows 등록 목록도 다시 읽습니다. 삭제는 바로가기 등록만 지우며 원본 프로그램·파일·폴더는 유지됩니다.
- 바로가기는 넓은 화면에서 한 줄 4개, 작은 화면에서 3개로 표시하며 페이지당 최대 12개를 등록합니다. 기존에 저장한 페이지와 항목 위치는 유지합니다. `+ 페이지`로 빈 페이지를 추가하고 선택한 페이지의 빈 추가 칸으로 등록할 수 있으며 페이지 구분은 DB에 저장됩니다. 아이콘 우클릭 또는 Shift+F10으로 이름·이미지를 간단히 바꾸고, 아래 월간 캘린더에서 이전/다음 달과 오늘을 확인합니다.
- 웹사이트는 Chrome·Edge 북마크에서 선택해 이름과 주소를 채울 수 있습니다. 여러 프로필과 폴더를 표시하고 브라우저·프로필 필터 및 이름·주소 검색을 지원합니다. 북마크는 버튼을 누를 때만 이 PC에서 읽으며 원본을 수정하지 않습니다.
- 채팅은 설정된 Gemma의 native 도구 호출로 요청을 이해하고 실제 기능을 실행합니다. `포샵이랑 일러스트, 코덱스 바로가기로 만들어줘`, `포토샵 좀 켜줄래?`처럼 말하면 설치 목록에서 대상을 찾아 등록·열기로 이어집니다. 앱 철자나 정해진 문장을 요구하지 않으며 실제 여러 후보가 있으면 채팅 선택 버튼을 사용합니다. 등록 요청만으로 앱을 실행하지 않습니다.
- 채팅 업무 등록·마감일과 진행 메모·상태 변경·자료 연결은 기존 업무 리스트와 같은 기록을 사용합니다. 보고서 생성·저장은 기존 채팅/API 기능으로 보존하며 기본 화면에 별도 패널을 두지 않습니다.
- 공통 도구 등록부에 앱·바로가기 조회/등록/편집/제거/열기, 북마크 조회·등록·열기, 업무·상태·메모·자료 연결·보고, 바탕화면 자료 조사·내용 분석·중복 조사·가상 작업함·복구 보관/복원을 연결했습니다. 전용 Chrome의 사이트 읽기·화면 확인, 문서 본문 검색과 Windows UI Automation 요소 조작도 채팅에서 요청할 수 있습니다. 메신저 수신·전송과 실제 스트림덱 기기 연결은 후속 단계입니다. AI 답변의 완료 주장만으로 수행 결과를 만들지 않습니다.
- 작업 데스크 첫 화면의 `AI가 살펴본 바탕화면`: 파일을 고르지 않아도 실제 지원 문서와 이미지의 내용·용도를 읽고, 근거가 있는 관련 자료를 앱 작업함에 자동 반영합니다. 빈 메모·보존할 자료·정리 후보를 구별하며 변경한 자료만 다시 확인합니다.
- 이미지 용도 판단: 작업 결과물·로고·참고 자료·짤·사진·스크린샷·초안과 실제 업무 관계를 Gemma 비전 모델로 검토합니다. 단순한 이미지나 오래된 파일을 불필요하다고 확정하지 않습니다.
- 후보 확인 창에서 파일 바로 열기, 남겨두기 기억, 표시한 후보만 한 번에 복구 보관함으로 치우기와 원위치 복원을 지원합니다. 분석 읽기는 사용자 사용 이력에 포함하지 않습니다.
- 기본 시작 화면인 작업 데스크: 실제 Windows 바탕화면의 앱·폴더·자료 검색, 유형별 보기, 즐겨찾기, 기본 앱으로 열기와 탐색기 위치 보기
- 관련 이름의 자료를 앱 안의 작업함으로 자동 정리합니다. 자동정리 일시 정지·최근 자동 묶음 되돌리기·작업함 이름 변경·항목 빼기를 지원합니다.
- 작업 데스크를 보고 있는 동안 30초마다 변화를 확인합니다. 변경이 있을 때만 화면을 갱신하고 새 관련 자료를 자동으로 묶습니다. 데스크를 닫으면 이 확인은 멈춥니다.
- 정리 제안함에서 대표 자료와 전체 파일명을 확인하고, 내용이 같은 파일은 별도의 읽기 전용 SHA-256 비교로 확인합니다.
- 작업 데스크의 `정리 실행 연습`: 앱이 만든 샘플을 실제 폴더로 자동 정리하고 결과·보류 사유를 표시합니다. 실행 기록은 새로고침 후에도 유지되며 중단된 정리 이어가기와 되돌리기를 지원합니다.
- `자동 폴더 정리`: 독립 파일 수신함과 보관 폴더, 제외 이름을 한 번 저장하고 미리보기를 확인합니다. 자동 시작 후 앱 실행 중 60초마다 지원 파일을 정리하며 결과·보류·최근 기록을 표시합니다. 계획 취소, 중단 재개, 되돌리기를 지원합니다.
- PC 자료 읽기 전용 조사, 유형·폴더별 현황 카드, 프로젝트·버전 검토 후보
- 텍스트·코드·DOCX·PDF 미리보기와 선택한 파일 최대 8개의 설정된 Gemma 서버 후보 분석
- PNG·JPEG·WebP·PSD·AI를 선택해 설정된 Ollama 비전 Gemma 서버로 시각 내용을 검토하는 카드
- ZIP 내부 구성 및 동일 파일 비교
- 저장한 범위의 지원 파일을 Windows 핸들로 잠금 확인하고 덮어쓰기 없이 이동
- GitHub fast-forward 업데이트, DB·설정 백업 및 제한된 실패 복구

## 데이터 보호

채팅 입력은 Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 한글 조합 확정 Enter와 처리 중 중복 입력은 전송하지 않습니다.

- `office.db`, `settings.json`, 로그, 업데이트 상태, 백업, Python 캐시는 Git 추적에서 제외합니다.
- 즐겨찾기는 `desktop_state.json`에 별도로 저장하며 Git에서 제외하고 업데이트 백업·복구에 포함합니다.
- 작업함·보류 제안·자동정리 설정과 되돌릴 묶음 기록도 같은 설정에 저장합니다. 기존 즐겨찾기는 유지됩니다. 가상 묶음은 원본을 이동·삭제하지 않으며, 파일명 분류는 업무 관계나 최신본의 확정 근거가 아닙니다.
- 시험 파일과 실행 기록은 Git에서 제외한 `organizer_lab`에 보관합니다. 샘플 4개를 정리하고 AI 연결 자료 샘플 1개는 보류합니다. 현재 시험 실행 API는 사용자 폴더 경로를 받지 않습니다.
- 실제 정리 설정은 `organizer_policy.json`, 실행 기록은 `organizer_runtime`에 보관하며 Git에서 제외합니다. 범위 승인과 정책 버전을 실행·되돌리기마다 독립적으로 확인합니다. 업데이트 실패 복구 시 자동 실행을 끄고 더 최근의 실행 기록을 보존합니다.
- 자동 판단 기록·요약·사용 이력은 `desktop_ai_state.json`, 승인 후 보관·복원 기록은 `desktop_recovery`에 별도로 저장하고 Git에서 제외합니다. 승인한 파일은 사용자 바탕화면의 숨김 폴더 `.AI_OFFICE_복구보관함`에 같은 드라이브 안에서 옮깁니다. Windows 휴지통이나 영구 삭제 기능이 아니며 한 번에 원위치 복원할 수 있습니다.
- 본문·이미지 자동 분석을 켜면 지원하는 실제 바탕화면 자료의 발췌·미리보기를 설정한 Gemma 서버로 전송합니다. 텍스트 비밀정보 패턴을 감지하면 전송을 보류하고, 모델 응답에도 민감정보 보호를 적용합니다. 이미지의 민감정보 검출과 의미 판단은 완전한 보장이 아닙니다.
- 실제 자동 정리는 독립 파일 수신함의 최상위 지원 파일만 대상으로 합니다. 드라이브·홈·시스템·Git 저장소·네트워크 폴더, 하드링크·재분석 경로는 제외합니다. AI·PSD·영상 프로젝트 원본이 있는 폴더는 연결 자료 보호를 위해 실제 이동을 보류합니다. 폴더 밖에서 참조하는 연결 관계를 자동 탐지하는 기능은 아직 없습니다.
- 파일당 20MB·한 번에 100개·합계 200MB로 제한하며 최근 수정 파일은 10초 기다립니다. 파일과 상위 폴더 핸들을 유지한 이동으로 일반 동시 편집과 경로 교체를 차단합니다. 충돌·사용 중 파일은 예외로 남기고 임의 삭제·덮어쓰기를 하지 않습니다.
- 실제 이동 실행기는 같은 Windows 드라이브에서 이름 충돌 시 덮어쓰지 않고, 파일 내용·식별 정보·수정 시각을 다시 확인합니다. 되돌릴 때 바뀐 파일과 새로 생긴 같은 이름의 파일은 확인 대상으로 남깁니다. 현재 검증 범위는 프로세스 중단 후 복구이며 전원 장애나 악의적인 동시 경로 교체까지 보장하지 않습니다.
- 작업 데스크의 분류는 확장자·폴더 정보 기준입니다. 바탕화면 최상위 항목만 표시하며 파일을 이동하거나 삭제하지 않습니다. 앱 실행은 항목을 누를 때만 요청합니다. 보호 파일·실행 스크립트는 직접 실행하지 않습니다.
- PNG·JPEG·WebP 썸네일은 이 PC에서 읽기 전용으로 생성합니다. AI 자동 분석을 켜둔 경우 앱을 다시 실행하면 지원 자료의 변경분 분석을 재개합니다.
- 내용 분석은 파일을 읽기만 합니다. 분석 결과는 후보이며 이동·삭제를 실행하지 않습니다.
- 업무 자료 연결은 사용자가 입력·선택한 로컬 파일·폴더 위치를 DB에 등록합니다. 등록 과정에서 파일 내용을 읽거나 전송·이동하지 않습니다. 실행 파일·스크립트·비밀 설정·링크 경로를 차단하고 자료를 열 때도 다시 확인합니다.
- 업무·자료·진행 기록·대화·보고서·중복 요청 결과는 기존 `office.db`의 추가 테이블에 저장합니다. 기존 업무 테이블과 행은 보존하며 사용자 기록은 Git에서 제외합니다. 같은 요청을 다시 보내도 변경은 한 번만 반영합니다.
- 실행판 등록·아이콘·순서·요청 기록도 `office.db`에 저장해 Git 제외와 기존 업데이트 백업을 적용합니다. 웹은 HTTP/HTTPS, 프로그램은 로컬 EXE/LNK 또는 서버에서 확인한 시작 메뉴 앱 참조, 폴더는 로컬 경로를 사용합니다. 시작 메뉴 앱은 실행 직전 등록 상태를 다시 확인합니다. 아이콘 이미지는 PNG/JPEG/WebP/ICO 512KB·1024px 이하를 검증해 PNG로 저장합니다.
- 앱 발견은 Windows `Get-StartApps` 기준이며 Windows 검색의 문서·웹·설정·개인별 순위는 포함하지 않습니다. 앱 ID가 같으면 중복을 제거하고 서로 다른 등록 ID는 같은 이름이어도 유지합니다. 외부 웹 주소 등 지원하지 않는 등록은 개수를 표시하고 제외합니다. Windows 목록을 읽지 못할 때는 기존 로컬 바로가기 최대 50개로 대체하며 출처를 표시합니다.
- 자연어 실행 요청·각 도구 단계·선택·승인을 기존 비공개 DB의 추가 테이블에 보관합니다. 모델 호출 중 DB 쓰기 트랜잭션을 유지하지 않으며, 요청/단계를 먼저 예약해 같은 요청의 중복 실행과 중단된 외부 효과의 자동 재실행을 막습니다. 중간에 일부 작업이 완료된 뒤 오류가 나면 실제 완료한 단계와 실패를 보고합니다. 새로고침 후에도 선택·승인 카드가 남고 서버에 보관한 대상만 처리합니다.
- 모델은 서버가 발급한 참조로 기능을 호출하며 임의 경로·AppID·셸 명령을 전달해 실행할 수 없습니다. 현재 한 요청의 도구 선택은 모델 왕복 최대 6회·도구 호출 최대 12회이며, 도구 없이 끝난 최초 답변에는 의도 검증 1회를 추가할 수 있습니다. 앱 이름은 Windows에 등록된 표시 이름을 사용하며, 패키지 식별자에서 제품 이름을 추측하지 않습니다.
- 약칭이나 앱 종류가 모호하면 관련된 실제 설치 후보를 보여주고 선택을 묻습니다. 바로가기 등록은 개별 선택·전부 추가·취소를 지원하며, 앱 실행은 개별 선택만 가능합니다. 전체 등록 결과는 추가·기존 유지·실패 건수를 구분합니다.
- 채팅에 “내 지클리커 스트림덱의 바로가기를 전부 가져와줘”라고 요청하면 G-Clicker의 저장된 웹·앱 바로가기를 등록합니다. 원본 프로필과 기존 타일은 유지하며, 반복 요청은 같은 대상을 중복 등록하지 않습니다. 지원하는 원본 아이콘은 PNG로 가져오고 나머지는 기본 아이콘을 사용합니다.
- G-Clicker 가져오기는 `%APPDATA%/HotSpot/StreamDock/profiles`의 현재 `.sdProfile/manifest.json`만 읽습니다. 앱 선택 목록 전체가 아니라 각 버튼의 선택된 앱만 가져옵니다. 암호·매크로·복합 동작·다른 플러그인·백업 ZIP은 제외합니다. 조회 도구는 이름·종류·서버 참조만 AI에 제공하고 실행 대상·아이콘은 서버 안에서 처리합니다. 앱을 실행하거나 원본을 수정하는 기능이 아닙니다. 현재 Elgato 프로필 가져오기와 일반 프로그램 화면 조작은 지원하지 않습니다.
- 가져오기는 한 번에 최대 500개이며 모델에 개별 이름을 보여주는 목록은 앞의 100개입니다. 파일당 8MB, 전체 프로필 32MB·100개, 탐색 깊이 16단계 등의 한도와 제외·실패 결과를 표시합니다. 문서 본문·암호 설정은 이 가져오기 도구에 포함되지 않습니다.
- 실제 파일 보관·복원은 고정된 후보와 revision을 가진 채팅 승인 카드에서만 실행합니다. 가상 작업함 분류는 실제 파일 이동과 구분해 보고합니다. 기존 실제 폴더 자동정리 정책은 채팅에서 상태·미리보기만 지원하며 실행·재개는 기존 자동 폴더 정리 화면을 사용합니다. 영구 삭제·외부 전송은 이 도구 등록부에 연결하지 않았습니다.
- 북마크는 표준 Chrome·Edge 사용자 데이터의 Default 및 Profile 번호 폴더에서 읽습니다. 파일당 8MB, 브라우저별 40개 프로필, 전체 5,000개 항목 한도와 읽기 실패를 표시합니다. 북마크 전체 목록은 DB·Git·AI 서버에 저장하거나 전송하지 않으며, 선택해 저장한 바로가기만 기존 DB에 남습니다. 사용자 지정 브라우저 데이터 경로와 다른 브라우저는 포함하지 않습니다.
- 내용 분석은 설정 메뉴에 등록한 Gemma 서버(Ollama 또는 OpenAI 호환 API)를 사용합니다. PC 조사 화면의 수동 분석은 선택한 파일을 사용하고, 작업 데스크의 자동 분석은 지원하는 바탕화면 자료를 차례로 사용합니다. 낮은 신뢰도는 보류합니다.
- 이미지 분석은 설정된 Ollama 서버의 지원 비전 모델을 사용합니다. 자동 판단을 켜면 이미지 내용도 순차적으로 살펴보며, 내용으로 확인된 연관성은 앱 작업함에 반영합니다. 실제 업무별 물리 폴더 이동은 아직 연결하지 않았습니다.
- 이미지 검토는 한 번에 3개, 원본 8MB·2천만 화소까지입니다. Pillow가 없는 경우 1600px·2MB 이하의 정지 PNG·JPEG·WebP만 처리합니다. PSD 미리보기에는 Pillow, AI 미리보기에는 설치된 Illustrator와 Pillow가 필요하며 첫 아트보드만 처리합니다. AI 파일의 외부 링크 이미지는 미리보기에 빠질 수 있습니다.
- 텍스트 파일은 최대 8MB까지 열고 6,000자까지만 표시합니다. DOCX 내부 확장 크기와 PDF 크기·페이지 수에도 제한을 둡니다.
- PDF 내용 추출은 선택적 `pypdf` 설치가 필요합니다. 설치되지 않은 환경에서는 안내 오류를 표시합니다.

## 채팅으로 사이트·문서 확인

- `https://사이트주소 열고 납기와 배송비를 찾아줘`: 별도 Chrome 창에서 사이트를 열고 실제 표시된 본문을 읽습니다. 열린 페이지의 링크를 따라가거나 스크롤하고 검색·요약할 수 있습니다. 기존 웹 바로가기와 북마크 열기도 같은 창을 사용합니다.
- `지금 열린 사이트의 그림이 무엇인지 화면을 보고 알려줘`: 실제 화면 이미지를 설정된 Ollama 비전 모델에 보내 확인합니다. 입력란과 iframe/frame 전체를 가리고, 가린 범위는 읽지 않았다고 표시합니다. 본문·그림에 직접 표시된 개인정보까지 자동으로 모두 가리는 기능은 아닙니다.
- `행사 안내 문서에서 납품일을 찾아줘`: 바탕화면 하위 폴더·설정한 작업 폴더·업무에 연결한 자료·PC 조사 목록에서 지원 문서를 찾아 본문을 읽습니다. 텍스트·코드·DOCX·HWPX·PDF 검색, 발췌와 요약을 지원하며 파일을 수정하거나 클립보드를 바꾸지 않습니다. HWP·구형 DOC·스캔 PDF의 OCR은 지원하지 않습니다.
- 문서는 파일당 8MB·추출 본문 12만 자·PDF 앞 60페이지까지, 한 번의 본문 응답은 1만 2천 자까지입니다. 검색은 추출한 전체 범위에서 수행하며 잘린 내용·읽지 못한 페이지를 표시합니다. 문서 발견은 500개·폴더 100개·탐색 깊이 3단계·항목 2,000개로 제한합니다.
- Chrome은 Git에서 제외한 `browser_runtime/`의 전용 프로필을 사용합니다. 기존 Chrome 창의 탭이나 쿠키는 가져오지 않습니다. 필요한 사이트는 이 전용 창에서 한 번 로그인하세요. 프로필은 이 PC에만 남고 업데이트 백업·Git 전송에 포함되지 않습니다.
- 웹 읽기는 메인 프레임의 표시된 텍스트 최대 6만 자, 한 번의 응답 1만 2천 자까지입니다. 로그인·동적 로딩·사이트 차단 등에 따라 읽지 못할 수 있으며 iframe·숨겨진 내용·입력값은 읽지 않습니다. 자동 로그인·양식 제출·파일 업로드·임의 클릭·다운로드는 연결하지 않았습니다.
- 새 환경은 앱을 실행하는 Python으로 `python -m pip install -r requirements.txt`를 실행하고 Chrome을 설치하세요. 이 PC에는 필요한 모듈을 설치했습니다. Playwright가 없으면 기존 웹 바로가기는 일반 브라우저 열기로 대체하고 화면 읽기 불가를 안내합니다.

검증 명령: `python -m unittest discover -s tests`, `node --test tests/test_workdesk_keyboard.cjs`.

## 공통 Windows 실행 계층

- 채팅 요청은 현재 기능 확인 → 대상 창·요소 관찰 → 지원 동작 수행 → 새 상태 확인으로 이어집니다. 매 요청에 실제 연결 상태를 전달하므로, 관리 Chrome으로 열 수 있는 웹사이트에 Windows 기본 브라우저 변경이 필요하다고 안내하지 않도록 했습니다.
- `계산기를 열고 현재 모드와 표시 값을 확인해줘`, `계산기의 7 버튼을 눌러줘`, `○○ 창의 입력란에 … 입력해줘`처럼 요청합니다. UI Automation이 제공하는 텍스트·버튼·입력란·선택 항목을 읽으며, 앱이 지원하는 포커스·버튼 실행·값 입력·선택·펼치기·접기·토글·스크롤을 사용합니다.
- 앱 실행·연결된 웹 기능·화면 조회·포커스·스크롤·펼치기·탭 이동은 요청에 따라 수행합니다. 의미가 아직 검증되지 않은 일반 앱의 버튼 실행·입력·토글·기타 선택은 실제 앱·대상·현재 상태·입력값을 묶어 한 번 확인받습니다. 승인 후에는 원래 요청을 자동으로 이어가고, 앞서 완료한 도구 결과와 중복 실행 방지를 유지합니다. 모든 버튼을 무인 실행하는 상태는 아닙니다.
- 참조는 관찰한 창·요소·문서 문맥·상태와 연결되며 90초 후 만료됩니다. 승인 전 다른 문서나 화면으로 바뀌면 실행을 보류합니다. 요소 호출 성공과 업무 전체 완료를 구별하고, 새 화면을 읽지 못하면 결과 미확인으로 남깁니다.
- 현재 일반 Windows 화면 연결은 UIA 텍스트 기반입니다. 그림·캔버스의 이미지 판단, 임의 좌표·키보드 명령, 관리자/UAC·인증·암호 관리자·보안 화면은 포함하지 않습니다. UIA를 제공하지 않는 앱은 읽기·조작이 제한됩니다. 웹 화면의 이미지 확인은 기존 Chrome 비전 기능을 사용합니다.
- 최대 60개 창·180개 요소·깊이 8단계·텍스트 1만 2천 자를 읽습니다. 오래 걸리는 UIA 요청은 30초 후 결과 미확인으로 안내하며, 아직 시작하지 않은 요청은 취소합니다. 이미 시작한 Windows 호출은 뒤늦게 끝날 수 있으므로 자동으로 재실행하지 않습니다.
- 필요한 Windows 모듈은 `requirements.txt`의 pywinauto입니다. 암호 입력란·인증정보 값은 모델 전달과 조작에서 제외하며, UIA 문자열은 실행 지시가 아닌 자료로 취급합니다. PC 조작 기록과 승인 정보는 기존 비공개 DB에 보관합니다.
- 도구를 한 번도 쓰지 않고 끝난 최초 답변은 의미 기반 검증기로 다시 판단합니다. 실행 요청이면 등록된 읽기 도구로 현재 상태를 실제 조회한 뒤 기존 실행을 이어갑니다. 취소·설명 요청은 실행으로 바꾸지 않으며, 검증 오류를 권한 부족으로 설명하지 않습니다. 이 검증도 AI 판단이므로 모든 의도 오류를 보장해 막지는 않습니다.
- Windows 설정은 기본 앱·디스플레이·소리·알림·저장소·앱 화면으로 직접 들어갈 수 있습니다. 기본 앱은 등록된 프로그램을 선택해 해당 설정 페이지를 열고 UIA로 확인합니다. HTTP/HTTPS UserChoice 기록만으로 실제 적용을 단정하거나, 설정 화면을 연 것만으로 변경 완료를 보고하지 않습니다. 레지스트리 기본값·보호 해시는 수정하지 않습니다.
- Chrome 창을 닫은 후 다음 바로가기의 첫 열기가 실패하던 수명주기 문제를 수정했습니다. 사이트 이동 전에 닫힌 창이 확인된 경우만 전용 창을 다시 만들며, 이미 시작한 사이트 이동이나 원인이 불명확한 오류는 자동으로 반복하지 않습니다.

## 실행 및 업데이트

- 연결 설정에서 기본 모델과 이미지 분석 모델을 따로 지정할 수 있습니다. 이미지 분석 모델을 비워두면 기본 모델을 사용합니다. 이미지 입력을 지원하지 않는 GGUF 모델을 기본으로 쓰는 경우에는 기존 이미지 지원 모델을 별도로 지정하세요. 일반 Ollama 응답은 추론 모드를 끄며, 작업별 명시적 추론 설정은 유지합니다.

- `start.bat`은 현재 설치된 버전을 실행합니다.
- `업데이트 후 실행.bat`은 `updater.py`를 통해 저장소·변경 상태를 확인하고, 업데이트 전에 DB와 설정을 백업합니다.
- 업데이트는 `main`의 fast-forward만 적용합니다. 실패하면 업데이트가 변경한 파일과 커밋만 조건부로 복구합니다.
- 백업은 `local_backups`에 저장됩니다. 오래된 백업은 사용자가 직접 확인한 뒤 관리하세요.

실행 절차와 주의 사항은 [UPDATE_GUIDE.md](UPDATE_GUIDE.md)를 참고하세요.

## 1차 기능 보고서와 테스트

실행 중인 앱의 `자동 폴더 정리 → 1차 기능 보고서·사용 안내` 또는 [first-release.html](first-release.html)에서 기존 기능 범위와 짧은 테스트 순서를 확인할 수 있습니다. 최신 사이트·문서·Windows 기능은 위의 채팅 예시를 사용하세요. 자동 삭제·내용 판단에 따른 무인 이동과 일반 앱의 무제한 자율 조작은 이후 단계입니다.
