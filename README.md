# AI OFFICE · 로컬 업무 콘솔

AI OFFICE는 빠른 실행·스트림덱·채팅 지시로 업무를 관리하고 대행하는 Windows 설치형 제품을 목표로 합니다. 업무 등록·관련 자료·메신저 수신과 전송·처리 이력·일일 보고서를 하나의 업무 흐름으로 연결하며, 파일 정리는 이를 돕는 부수 기능입니다. 제품화·개인별 AI 연결·수익화까지의 방향은 [AUTOMATION_DIRECTION.md](AUTOMATION_DIRECTION.md)에 정리했습니다. 이 문단은 제품 목표이며 아래 목록이 현재 구현 범위입니다.

## 주요 기능

- 화면은 차콜 패널·겹테두리·라임 그린 선택 표시를 사용하는 레트로 콘솔 스타일입니다. 한글 Pretendard와 영문·숫자 Barlow Condensed 서체를 앱에 포함해 인터넷 없이 표시하며, 배포 출처와 라이선스는 `assets/fonts/`에 보관합니다. 채팅·자료·설정·팝업·사용 안내에 같은 스타일을 적용합니다.
- 기본 운영 화면은 전체 모니터 높이에 맞춘 왼쪽 채팅·오늘의 업무, 중앙 카드 보드, 오른쪽 WORKSPACE의 3열입니다. 상단 안내 문구를 제거하고 보조 도구는 왼쪽 메뉴 하단에 배치합니다. 세 영역의 하단을 맞추고 대화·업무·카드·결과는 각 영역 안에서 스크롤합니다. 업무 상태와 기록·자료 수는 업무 행의 배지로 확인하며 업무를 누르면 상세 팝업이 열립니다. 별도 업무 확인·기록 창은 두지 않습니다.
- 모니터 한 대를 전용으로 사용하는 데스크톱 업무 공간을 기준으로 합니다. Aemeath 아래에 미니 캘린더를 배치합니다. WORKSPACE는 실제 요청의 도구 진행 기록과 별도로 작성·게시한 코드·문서·요약 결과물, 선택한 이미지·영상 미리보기를 표시합니다. 일반 채팅 답변과 단순히 읽은 웹·문서 본문을 자동 복제하지 않습니다. 이미지와 영상은 확대할 수 있습니다. 모델 응답은 현재 스트리밍이 아니므로 코드·요약은 도착한 뒤 표시하며, 생성한 코드의 표시가 실제 실행을 뜻하지 않습니다. 메신저 수신 파일은 아직 이 화면에 연결하지 않았습니다.
- 채팅 옆의 Aemeath 캐릭터는 대기·입력·요청 처리·답변 도착·저장·확인 필요 상태에 맞춰 움직입니다. 사용자 제공 GIF를 사용하며, 동작 줄이기 설정에서는 정지 화면을 표시합니다. 캐릭터의 반응은 화면의 요청 상태를 나타내며 실제 앱 실행이나 업무 전체 완료를 보장하는 표시는 아닙니다.
- 세 패널의 윗선은 AI OFFICE 브랜드 아래 초록색 선에 맞추고, 위 여백에는 “Your day, in good hands.”를 표시합니다. 캘린더 아래에는 한국 시각의 디지털 시계와 사용자 지정 지역인 경기도 의정부의 날씨·기온을 작게 표시합니다. 시계는 날씨 연결 상태와 독립적으로 동작하며 날씨에는 갱신 시각과 연결 상태를 표시합니다.
- 에이메스는 다정하고 밝은 여동생 같은 반말을 사용합니다. 원문·파일 이름·코드·공식 문서의 문체와 실제 작업 결과는 유지하며, 과거 대화 기록을 다시 쓰지 않습니다.
- 바로가기는 추가·수정·삭제·순서 변경·이모지/이미지 아이콘을 지원합니다. GIF 아이콘은 움직임·재생 간격·투명도를 보존합니다. 아이콘 업로드는 512KB·가로세로 각 1024px 이하이며, GIF는 최대 300프레임·누적 3,200만 화소까지 확인합니다. 아이콘 우클릭으로 전체 설정을 열어 이름·종류·실행 대상·아이콘과 순서를 바꾸며, 카드 보드 전체에서 드래그로 순서를 저장합니다. Windows 시작 메뉴의 일반 설치 앱·Store 앱을 이름으로 검색해 등록하거나 실행 파일을 직접 선택합니다. 목록 새로고침은 Windows 등록 목록도 다시 읽습니다. 삭제는 바로가기 등록만 지우며 원본 프로그램·파일·폴더는 유지됩니다.
- 바로가기는 페이지 버튼 없이 4열 카드 보드를 세로 스크롤합니다. 기존 각 페이지의 항목은 순서대로 모으며, 원래 항목·페이지·아이콘과 분리된 보드 순서 테이블을 사용합니다. 카드 높이는 표지·설명에 맞춰 배치합니다. 우클릭 또는 Shift+F10에서 160자 설명과 별도 커버 이미지·GIF를 넣고, 전체 보드에서 드래그로 순서를 바꿉니다. 커버는 PNG/JPEG/WebP/GIF, 최대 4MB·2048px이며 애니메이션 원본을 유지합니다. 작은 실행 아이콘의 512KB 제한과 구별합니다. 이름·대상·아이콘·설명·커버는 같은 요청으로 저장하며 저장 직후 화면에 반영합니다. 미니 캘린더와 Aemeath 채팅은 함께 표시합니다.
- 카드 커버 권장 규격은 가로:세로 3:2, 600×400px 또는 1200×800px입니다. 이름·주소·W/P/F 배지는 화면에서 따로 표시하므로 이미지 안에 넣을 필요가 없습니다. 커버가 없으면 기존 아이콘 이미지를 채워 표시하며 비율이 다른 원본 가장자리는 잘릴 수 있습니다.
- 웹사이트는 Chrome·Edge 북마크에서 선택해 이름과 주소를 채울 수 있습니다. 여러 프로필과 폴더를 표시하고 브라우저·프로필 필터 및 이름·주소 검색을 지원합니다. 북마크는 버튼을 누를 때만 이 PC에서 읽으며 원본을 수정하지 않습니다.
- 기본 채팅은 ChatGPT 구독으로 인증한 Codex GPT-6 Luna가 요청과 도구 사용을 판단하고, AI OFFICE의 기존 실행기가 검증·승인·기록을 거쳐 실제 기능을 실행합니다. Codex 자체의 셸·파일 수정·외부 도구는 이 연결에서 사용하지 않습니다. `포샵이랑 일러스트, 코덱스 바로가기로 만들어줘`, `포토샵 좀 켜줄래?`처럼 말하면 설치 목록에서 대상을 찾아 등록·열기로 이어집니다. 앱 철자나 정해진 문장을 요구하지 않으며 실제 여러 후보가 있으면 채팅 선택 버튼을 사용합니다. 등록 요청만으로 앱을 실행하지 않습니다.
- ‘파일 찾기’와 채팅의 파일 검색은 같은 서비스를 사용합니다. 문서·PSD·이미지·압축파일·폴더를 바탕화면·문서·다운로드·설정 작업 폴더·연결 자료·기존 조사 결과에서 찾아 탐색기로 위치를 표시합니다. 파일 본문을 읽는 기능과 구별하며 검색 범위·제한을 표시합니다. 실제 경로와 파일 신원을 재확인하고 같은 요청의 중복 실행을 방지합니다.
- 이미 저장·허용한 폴더 정리 정책은 채팅에서도 상태·미리보기·한 번 실행·자동 처리 켜기/끄기·재개·되돌리기를 사용할 수 있습니다. 화면 버튼과 같은 실행기·이력을 사용하며 실행 전에 관찰한 범위를 다시 확인합니다. 응답이 불확실하면 같은 요청 결과 확인을 제공합니다. 새 정리 범위 설정은 기존 화면에서 수행합니다.
- 바로가기 페이지 추가·이동, 조회한 앱·북마크·폴더로 실행 대상 변경, 검색한 이미지/GIF 아이콘 적용과 PC 조사 상태·결과 조회도 채팅에 연결했습니다. `지금 어떤 기능을 쓸 수 있어?` 같은 질문에 등록된 기능과 화면 전용·미연결 기능을 구별합니다. 한비로톡과 네이트온의 첨부 수신·저장·전달, 웹 양식 제출과 업무 매뉴얼 실행은 아직 전용 연결이 필요합니다. 메신저 로그인 상태만으로 연결 완료로 표시하지 않습니다.
- 채팅 업무 등록·마감일과 진행 메모·상태 변경·자료 연결은 기존 업무 리스트와 같은 기록을 사용합니다. 기존 예정·진행중·완료에 검토중 상태를 추가하며 기존 상태를 변환하지 않습니다. 보고서 생성·저장은 기존 채팅/API 기능으로 보존하며 기본 화면에 별도 패널을 두지 않습니다. 외부 일일보고서 사이트와 상태를 자동 동기화하는 기능은 후속 연결 단계입니다.
- 공통 도구 등록부에 앱·바로가기 조회/등록/편집/제거/열기, 북마크 조회·등록·열기, 업무·상태·메모·자료 연결·보고, 바탕화면 자료 조사·내용 분석·중복 조사·가상 작업함·복구 보관/복원을 연결했습니다. 전용 Chrome의 사이트 읽기·화면 확인, 문서 본문 검색과 Windows UI Automation 요소 조작도 채팅에서 요청할 수 있습니다. 메신저 수신·전송과 실제 스트림덱 기기 연결은 후속 단계입니다. AI 답변의 완료 주장만으로 수행 결과를 만들지 않습니다.
- 작업 데스크 첫 화면의 `AI가 살펴본 바탕화면`: 파일을 고르지 않아도 실제 지원 문서와 이미지의 내용·용도를 읽고, 근거가 있는 관련 자료를 앱 작업함에 자동 반영합니다. 빈 메모·보존할 자료·정리 후보를 구별하며 변경한 자료만 다시 확인합니다.
- 이미지 용도 판단: 작업 결과물·로고·참고 자료·짤·사진·스크린샷·초안과 실제 업무 관계를 Gemma 비전 모델로 검토합니다. 단순한 이미지나 오래된 파일을 불필요하다고 확정하지 않습니다.
- 후보 확인 창에서 파일 바로 열기, 남겨두기 기억, 표시한 후보만 한 번에 복구 보관함으로 치우기와 원위치 복원을 지원합니다. 분석 읽기는 사용자 사용 이력에 포함하지 않습니다.
- 기본 시작 화면인 작업 데스크: 실제 Windows 바탕화면의 앱·폴더·자료 검색, 유형별 보기, 즐겨찾기, 기본 앱으로 열기와 탐색기 위치 보기
- 관련 이름의 자료를 앱 안의 작업함으로 자동 정리합니다. 자동정리 일시 정지·최근 자동 묶음 되돌리기·작업함 이름 변경·항목 빼기를 지원합니다.
- 작업 데스크를 보고 있는 동안 30초마다 변화를 확인합니다. 변경이 있을 때만 화면을 갱신하고 새 관련 자료를 자동으로 묶습니다. 데스크를 닫으면 이 확인은 멈춥니다.
- 정리 제안함에서 대표 자료와 전체 파일명을 확인하고, 내용이 같은 파일은 별도의 읽기 전용 SHA-256 비교로 확인합니다.
- 작업 데스크의 `정리 실행 연습`: 앱이 만든 샘플을 실제 폴더로 자동 정리하고 결과·보류 사유를 표시합니다. 실행 기록은 새로고침 후에도 유지되며 중단된 정리 이어가기와 되돌리기를 지원합니다.
- `자동 폴더 정리`: 독립 파일 수신함과 보관 폴더, 제외 이름을 한 번 저장하고 미리보기를 확인합니다. 자동 시작 후 앱 실행 중 60초마다 지원 파일을 정리하며 결과·보류·최근 기록을 표시합니다. 계획 취소, 중단 재개, 되돌리기를 지원합니다.
- PC 자료 읽기 전용 조사, 유형·폴더별 현황 카드, 프로젝트·버전 검토 후보
- 텍스트·코드·DOCX·PDF 미리보기와 선택한 파일 최대 8개의 설정된 Gemma 서버 후보 분석
- PNG·JPEG·WebP·PSD·AI를 선택해 설정된 Ollama 비전 Gemma 서버로 시각 내용을 검토하는 카드
- ZIP 내부 구성 및 동일 파일 비교
- 저장한 범위의 지원 파일을 Windows 핸들로 잠금 확인하고 덮어쓰기 없이 이동
- GitHub fast-forward 업데이트, DB·설정 백업 및 제한된 실패 복구

## 에이메스의 프로젝트 맥락

- `PROJECT_CONTEXT.md`에 개발 채팅에서 확정된 화면 원칙, 사용자 결정, 코드 구조, 확인된 변경과 미완료 작업을 정리합니다. 전체 채팅 기록의 자동 동기화는 아닙니다.
- 각 새 요청은 `Core`의 짧은 내용을 실행 판단과 도구 계획 양쪽에 제공합니다. 상세 내용은 읽기 전용 `office_project_context`로 조회하며 `history`는 최근 12개 Git 변경 제목도 제공합니다. 실제 자체 수정 결과는 `office_source_history`와 실행 기록을 확인합니다.
- 오래된 기록은 새 실행 권한이나 완료 증명이 아닙니다. 현재 요청과 실제 소스·도구 결과를 우선하며, 문서가 없거나 읽을 수 없어도 일반 채팅은 계속 작동합니다. 다른 개발 창에서 결정이 바뀌면 이 문서도 함께 갱신해야 합니다.
- Codex 실행 판단은 엄격한 최상위 JSON으로 받습니다. 원래처럼 판단 JSON 전체를 응답 문자열 안에 넣지 않으며, 읽기 도구·인자는 기존 실행기가 다시 검증합니다. 응답 형식 실패에는 원문 대신 안전한 원인 코드만 기록합니다.

- 내용 분석은 설정 메뉴에서 선택한 Codex 또는 기존 Ollama·OpenAI 호환 연결을 사용합니다. PC 조사 화면의 수동 분석은 선택한 파일을 사용하고, 작업 데스크의 자동 분석은 지원하는 바탕화면 자료를 차례로 사용합니다. 낮은 신뢰도는 보류합니다.

## 채팅으로 사이트·문서 확인

- `https://사이트주소 열고 납기와 배송비를 찾아줘`: 별도 Chrome 창에서 사이트를 열고 실제 표시된 본문을 읽습니다. 열린 페이지의 링크를 따라가거나 스크롤하고 검색·요약할 수 있습니다. 기존 웹 바로가기와 북마크 열기도 같은 창을 사용합니다.
- `지금 열린 사이트의 그림이 무엇인지 화면을 보고 알려줘`: 실제 화면 이미지를 설정된 Ollama 비전 모델에 보내 확인합니다. 입력란과 iframe/frame 전체를 가리고, 가린 범위는 읽지 않았다고 표시합니다. 본문·그림에 직접 표시된 개인정보까지 자동으로 모두 가리는 기능은 아닙니다.
- `행사 안내 문서에서 납품일을 찾아줘`: 바탕화면 하위 폴더·설정한 작업 폴더·업무에 연결한 자료·PC 조사 목록에서 지원 문서를 찾아 본문을 읽습니다. 텍스트·코드·DOCX·HWPX·PDF 검색, 발췌와 요약을 지원하며 파일을 수정하거나 클립보드를 바꾸지 않습니다. HWP·구형 DOC·스캔 PDF의 OCR은 지원하지 않습니다.
- 문서는 파일당 8MB·추출 본문 12만 자·PDF 앞 60페이지까지, 한 번의 본문 응답은 1만 2천 자까지입니다. 검색은 추출한 전체 범위에서 수행하며 잘린 내용·읽지 못한 페이지를 표시합니다. 문서 발견은 500개·폴더 100개·탐색 깊이 3단계·항목 2,000개로 제한합니다.
- Chrome은 Git에서 제외한 `browser_runtime/`의 전용 프로필을 사용합니다. 기존 Chrome 창의 탭이나 쿠키는 가져오지 않습니다. 필요한 사이트는 이 전용 창에서 한 번 로그인하세요. 프로필은 이 PC에만 남고 업데이트 백업·Git 전송에 포함되지 않습니다.
- 웹 읽기는 메인 프레임의 표시된 텍스트 최대 6만 자, 한 번의 응답 1만 2천 자까지입니다. 로그인·동적 로딩·사이트 차단 등에 따라 읽지 못할 수 있으며 iframe·숨겨진 내용·입력값은 읽지 않습니다. 자동 로그인·양식 제출·파일 업로드·임의 클릭·다운로드는 연결하지 않았습니다.
- 새 환경은 앱을 실행하는 Python으로 `python -m pip install -r requirements.txt`를 실행하고 Chrome을 설치하세요. 이 PC에는 필요한 모듈을 설치했습니다. Playwright가 없으면 기존 웹 바로가기는 일반 브라우저 열기로 대체하고 화면 읽기 불가를 안내합니다.

검증 명령: `python -m unittest discover -s tests`, `node --test tests/test_workdesk_keyboard.cjs`.

## 공통 Windows 실행 계층

- 채팅 요청은 현재 기능 확인 → 대상 창·요소 관찰 → 지원 동작 수행 → 새 상태 확인으로 이어집니다. 매 요청에 실제 연결 상태를 전달하므로, 관리 Chrome으로 열 수 있는 웹사이트에 Windows 기본 브라우저 변경이 필요하다고 안내하지 않도록 했습니다.
- `계산기를 열고 현재 모드와 표시 값을 확인해줘`, `계산기의 7 버튼을 눌러줘`, `○○ 창의 입력란에 … 입력해줘`처럼 요청합니다. UI Automation이 제공하는 텍스트·버튼·입력란·선택 항목을 읽으며, 앱이 지원하는 포커스·버튼 실행·값 입력·선택·펼치기·접기·토글·스크롤을 사용합니다.
- 앱 실행·연결된 웹 기능·화면 조회·포커스·스크롤·펼치기·탭 이동은 요청에 따라 수행합니다. 의미가 아직 검증되지 않은 일반 앱의 버튼 실행·입력·토글·기타 선택은 실제 앱·대상·현재 상태·입력값을 묶어 한 번 확인받습니다. 승인 후에는 원래 요청을 자동으로 이어가고, 앞서 완료한 도구 결과와 중복 실행 방지를 유지합니다. 모든 버튼을 무인 실행하는 상태는 아닙니다.
- 참조는 관찰한 창·요소·문서 문맥·상태와 연결되며 90초 후 만료됩니다. 승인 전 다른 문서나 화면으로 바뀌면 실행을 보류합니다. 요소 호출 성공과 업무 전체 완료를 구별하고, 새 화면을 읽지 못하면 결과 미확인으로 남깁니다.
- 현재 일반 Windows 화면 연결은 UIA 텍스트 기반입니다. 그림·캔버스의 이미지 판단, 임의 좌표·키보드 명령, 관리자/UAC·인증·암호 관리자·보안 화면은 포함하지 않습니다. UIA를 제공하지 않는 앱은 읽기·조작이 제한됩니다. 웹 화면의 이미지 확인은 기존 Chrome 비전 기능을 사용합니다.
- 최대 60개 창·180개 요소·깊이 8단계·텍스트 1만 2천 자를 읽습니다. 오래 걸리는 UIA 요청은 30초 후 결과 미확인으로 안내하며, 아직 시작하지 않은 요청은 취소합니다. 이미 시작한 Windows 호출은 뒤늦게 끝날 수 있으므로 자동으로 재실행하지 않습니다.
- 필요한 Windows 모듈은 `requirements.txt`의 pywinauto입니다. 암호 입력란·인증정보 값은 모델 전달과 조작에서 제외하며, UIA 문자열은 실행 지시가 아닌 자료로 취급합니다. PC 조작 기록과 승인 정보는 기존 비공개 DB에 보관합니다.
- 새 채팅 요청은 최신 메시지와 참고용 과거 기록을 분리해 한 번 판단합니다. 일반 대화·설명·취소는 바로 답하고, 실행 요청만 등록된 읽기 도구로 현재 상태를 조회한 뒤 기존 실행을 이어갑니다. 예전 미완료 요청을 새 실행 지시로 재사용하지 않습니다. 승인 후 이어가는 실행은 원래 목표와 중복 실행 방지 기록을 유지합니다. 이 판단도 AI 응답이므로 모든 의도 오류를 보장해 막지는 않습니다.
- 백그라운드 바탕화면 분석과 채팅이 같은 로컬 모델을 사용할 때 채팅을 우선합니다. 이미 시작한 분석 요청은 마치고, 이후 분석 요청은 대화 처리가 끝날 때까지 기다립니다. 분석 사용 설정과 기존 결과는 유지합니다.
- Windows 설정은 기본 앱·디스플레이·소리·알림·저장소·앱 화면으로 직접 들어갈 수 있습니다. 기본 앱은 등록된 프로그램을 선택해 해당 설정 페이지를 열고 UIA로 확인합니다. HTTP/HTTPS UserChoice 기록만으로 실제 적용을 단정하거나, 설정 화면을 연 것만으로 변경 완료를 보고하지 않습니다. 레지스트리 기본값·보호 해시는 수정하지 않습니다.
- Chrome 창을 닫은 후 다음 바로가기의 첫 열기가 실패하던 수명주기 문제를 수정했습니다. 사이트 이동 전에 닫힌 창이 확인된 경우만 전용 창을 다시 만들며, 이미 시작한 사이트 이동이나 원인이 불명확한 오류는 자동으로 반복하지 않습니다.

## 실행 및 업데이트

- Codex 연결은 요청 사이에 재사용하고 대화마다 별도 임시 스레드를 사용합니다. 로그인·모델 목록 확인은 짧게 캐시하며, 대기 중 모델 추론은 호출하지 않습니다. 실행 의도 판단의 중복 설명을 줄이고 일반 답변은 채팅에 ‘작성 중’으로 먼저 표시합니다. JSON 도구 인수와 추론 내용은 표시하지 않으며 완료된 실행 기록과 최종 답변이 기준입니다. 실제 지연 감소량은 아직 측정하지 않았습니다.
- 에이메스에게 AI OFFICE의 작은 화면·기능 수정을 직접 요청할 수 있습니다. `런처 제목을 QUICK ACCESS로 바꿔줘`처럼 요청하면 허용된 실제 운영 소스를 조회하고, 읽은 원본 해시와 정확한 수정 구간을 확인해 즉시 저장합니다. WORKSPACE에는 실제 변경 diff를 표시합니다. 사용자 요청 없이 자동 개조하지 않습니다.
- 원본 검색은 파일명과 실제 본문의 검색어를 비교하고 일치하지 않아도 실제 원본 목록을 제공합니다. 소스 조회 후 편집 단계에는 관련 도구 설명만 보내며 모델 응답은 최대 180초 기다립니다. 일반 대화의 설정 대기시간은 유지하고, 시간 초과·연결 종료·응답 형식 오류는 안전한 코드와 처리 단계·경과 시간을 작업 기록에 남깁니다. 한글 수정 내용은 문자 이스케이프 때문에 불필요하게 제한하지 않습니다.
- 자체 수정은 기존 파일의 한 구간씩 수행하며 변경마다 원본을 `local_backups/self-edit`에 백업합니다. DB·설정·인증·사용자 이미지/GIF·Git 기록과 수정·재시작 보호 코드는 대상에서 제외합니다. ‘방금 수정한 내용 되돌려줘’ 요청은 이력을 조회하고 이후 다른 수정이 없는 경우에만 되돌립니다. Python과 가능한 JavaScript 구문을 확인하지만 실제 기능의 정상 동작을 보장하는 검사는 아닙니다.
- 화면 소스 변경은 완료 응답 뒤 새로고침합니다. Python 변경은 다른 요청·모델 처리·파일 정리가 끝나면 자동 재시작하며 새 브라우저 창을 열지 않습니다. 시작 실패 시 해당 소스 변경만 복구하며 개인 DB·설정은 복원하지 않습니다. 소스 저장과 실행 반영 상태는 구별해 표시합니다.
- 채팅 입력창의 파일 첨부 버튼·드래그·파일 붙여넣기로 한 요청에 최대 6개, 이미지·ZIP 10MB, 문서·코드 8MB·합계 30MB를 올립니다. 첨부는 해당 명령 ID에 저장한 뒤 메시지와 함께 확정하며 재시도는 같은 ID를 유지합니다. 원본은 Git에서 제외된 `local_backups/chat-files`에 저장하고 이름·형식 등 메타데이터만 먼저 모델에 전달합니다. 문서·코드·PDF·DOCX는 실제 본문 읽기, 이미지/GIF는 요청 시 샘플 프레임 분석, ZIP은 실행·압축 해제 없는 파일 목록 조회를 지원합니다. 문서 분석은 기존 8MB 제한을 따릅니다.
- 첨부 자료의 미리보기와 원본 다운로드를 대화·WORKSPACE에 연결했습니다. 올린 GIF·이미지를 에이메스 캐릭터에 추가·교체하라고 요청하면 기존 6개 상태 중 지정한 상태에 즉시 적용합니다. 상태를 지정하지 않은 추가 요청은 대기 상태에 등록하며 기존 GIF와 8초 간격으로 순환합니다. 원본 GIF의 화질·프레임·재생 속도는 그대로 보존하고 기존 기본 파일은 삭제하지 않습니다. 캐릭터 목록과 이전 설정 백업은 `local_backups/companion-assets`에 보관합니다.
- 올린 자료를 읽어 AI OFFICE 소스 수정에 활용할 수 있습니다. 이미지 자체를 새로 그리거나 픽셀을 편집하는 생성 엔진과 무제한 셸 실행은 별도 연결 범위입니다. 이번 변경은 GIF 원본을 앱에 등록·적용하는 작업을 포함합니다.

- 기본 AI 연결은 Codex 앱에 로그인한 ChatGPT 구독의 `gpt-6-luna`입니다. 낮은 추론과 일반 속도(Standard)를 고정하며 Fast나 다른 모델로 자동 전환하지 않습니다. Codex 실행 파일과 유효한 ChatGPT 로그인이 필요하며 별도 API 키를 사용하지 않습니다. LM Studio 실행과 E4B 로드는 필요하지 않습니다. 구독 한도와 추가 크레딧 사용은 해당 계정 정책을 따릅니다.
- Codex는 사용자가 채팅하거나 분석을 직접 요청할 때만 호출합니다. 앱을 켜거나 바탕화면에 띄워두는 것만으로 AI 분석을 반복하지 않습니다. 한 요청도 의도 판단·작업·결과 확인에 여러 모델 호출이 필요할 수 있습니다. 기존 분석 기록은 유지합니다. 선택 연결이 실패하면 오류를 표시하고 자동으로 다른 모델이나 API 과금 경로로 전환하지 않습니다.
- 채팅 답변은 대화창에만 표시합니다. 캐릭터 위 알림에는 직접 작업의 저장 결과와 실제 오류·결과 미확인 안내만 표시합니다.

- Ollama·OpenAI 호환 연결을 선택한 경우 기본 모델과 이미지 분석 모델을 따로 지정할 수 있습니다. 이미지 분석 모델을 비워두면 기본 모델을 사용합니다. 이미지 입력을 지원하지 않는 GGUF 모델을 기본으로 쓰는 경우에는 기존 이미지 지원 모델을 별도로 지정하세요. 일반 Ollama 응답은 추론 모드를 끄며, 작업별 명시적 추론 설정은 유지합니다.

- `start.bat`은 현재 설치된 버전을 실행합니다.
- `업데이트 후 실행.bat`은 `updater.py`를 통해 저장소·변경 상태를 확인하고, 업데이트 전에 DB와 설정을 백업합니다.
- 업데이트는 `main`의 fast-forward만 적용합니다. 실패하면 업데이트가 변경한 파일과 커밋만 조건부로 복구합니다.
- 백업은 `local_backups`에 저장됩니다. 오래된 백업은 사용자가 직접 확인한 뒤 관리하세요.

실행 절차와 주의 사항은 [UPDATE_GUIDE.md](UPDATE_GUIDE.md)를 참고하세요.

## 1차 기능 보고서와 테스트

실행 중인 앱의 `자동 폴더 정리 → 1차 기능 보고서·사용 안내` 또는 [first-release.html](first-release.html)에서 기존 기능 범위와 짧은 테스트 순서를 확인할 수 있습니다. 최신 사이트·문서·Windows 기능은 위의 채팅 예시를 사용하세요. 자동 삭제·내용 판단에 따른 무인 이동과 일반 앱의 무제한 자율 조작은 이후 단계입니다.

Codex 연결 근거: [App Server](https://learn.chatgpt.com/docs/app-server), [구독 사용량과 가격](https://learn.chatgpt.com/docs/pricing). 현재 계정의 모델 목록에서 GPT-6 Luna를 확인한 뒤 사용하며, 실제 사용 가능 여부는 완료된 응답으로 확인합니다.
