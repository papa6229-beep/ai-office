# 비즈호스트 상품 검수

현재 회사 PC의 `local_backups/bizhost-inspector/bin/BizhostInspector.exe`를 실행한다. 바탕화면 **비즈호스트 상품 검수** 바로가기도 같은 프로그램을 연다. 회의실에는 이 창을 미러링한다. 원격 제어/미러링 프로그램은 설치하지 않았으며 회사망에 새 포트를 개방하지 않는다.

오피스 LAUNCHER의 첫 카드 **비즈호스트 상품 검수**에도 같은 EXE를 연결했다. `launcher-cover.png`는 내장 image_gen으로 생성한 3:2 로봇 상품 검사 그림이다. 이미 열린 오피스에 카드가 없으면 런처의 **목록 새로고침**을 누른다. 카드는 프로그램을 열며 실제 검수는 프로그램 안의 **검수 시작** 버튼으로 실행한다.

## 실제 실행

1. **실제 반영 모드**를 확인하고 **검수 시작**을 누른다.
2. 기존 전용 Chrome 세션과 Windows 보관 계정으로 로그인한다. 문자 인증은 기존 휴대폰 연결 앱/오피스 수신 자료를 읽는다. 자동 수신이 없으면 이 화면의 인증번호 입력을 사용할 수 있다. 오피스 서버가 없어도 직접 입력으로 인증할 수 있다. 비밀번호/인증번호를 결과 파일이나 화면 로그에 저장하지 않는다.
3. A→B→C군 순서로 기존 기준을 적용한다. 정상이면 대표상품명 앞에 `[완료]`를 붙이고 실제 저장값을 다시 조회한다. 이미 완료/작업중/리얼돌/매장전용은 제외한다. 이미지 제목 일치는 필수 조건에서 제외한 현행 기준을 유지한다.
4. 부적격은 변경하지 않고 다음 상품을 처리한다. 전체 종료 후 문제·담당MD 목록과 **수정지시를 전달할까요?**를 표시한다. 복사/결과 내려받기만 제공하며 메신저 발신은 하지 않는다.

**검수 중지**는 진행 중 사이트 응답/저장 상태 확인 후 멈춘다. 이미 저장된 상품은 자동으로 되돌리지 않는다. 창을 닫아도 실행은 유지되며 같은 실행파일을 다시 열어 진행 상태를 볼 수 있다. 프로그램/PC가 강제 종료되면 영수증을 보존하고 자동 재실행하지 않는다.

## 보관과 범위

- 보고서 사이트를 열거나 보고서를 작성/저장하지 않는다.
- 반복 검수는 로컬 코드이며 모델 API/CLI를 호출하지 않는다.
- 기존 `browser_runtime/chrome-profile`을 재사용한다. 일반 Chrome의 계정/쿠키는 복사하지 않는다.
- 개인 실행 결과: `local_backups/bizhost-inspector/runs/<실행번호>/result.json`. 부적격·완료 항목은 확인된 실행 결과다.
- 화면은 `127.0.0.1:8876`에서만 제공한다. 루프백/Host/Origin/Fetch Metadata 검사와 요청 토큰을 사용한다. 회의실 PC에서 이 주소를 직접 열 수 있는 서비스는 아니다.
- 현재 PC 설치를 재사용하는 실행파일이므로 다른 PC에 EXE만 복사해서 실행하는 배포판이 아니다.
- `report_automation.py`의 공통 잠금은 새 코드를 불러온 보고서 실행기와 독립 실행기 사이에서 적용된다. 이미 메모리에 올라간 예전 오피스 모듈은 다음 서버 재시작부터 적용된다. 시연 중 오피스 보고서 검수를 동시에 실행하지 않는다.

빌드는 `build.ps1`이 설치된 Microsoft WebView2 SDK와 Python만 재사용한다. 네트워크 패키지 설치 없음.
